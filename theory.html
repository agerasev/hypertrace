Theory & implementation

Tracing light through curved space.

Hypertrace keeps the local rules of reflection and scattering, while changing the geometry that carries light between surfaces.

This guide develops the ideas in Alexey Gerasev’s original 2020 article and connects them to the current WGPU implementation. Watch the original walkthrough for a moving view of the project.

1. One kernel, three curvatures

Hypertrace constructs and traces Euclidean, hyperbolic and spherical scenes through one embedded representation. Points have scalar-first coordinates P = (w, x, y, z); write X = (x, y, z). The curvature sign K is −1, 0 or +1, and curved scenes choose a physical radius R > 0, giving sectional curvature K/R². Euclidean scenes use R = 1.

BK(P,Q) = PwQw + K X · Y
SpaceEmbedded pointsCK(t)SK(t)
Hyperbolic H³w² − ‖X‖² = 1, w > 0cosh tsinh t
Euclidean E³w = 11t
Spherical S³w² + ‖X‖² = 1cos tsin t

A ray stores its point and an ambient tangent V. Curved unit tangents satisfy B(P,V) = 0 and B(V,V) = K. In Euclidean space, Vw = 0 and its spatial part has unit length; the degenerate form at K = 0 cannot define tangent lengths. With t = s/R in curved spaces and t = s in Euclidean space, advancement by physical distance s is:

P(t) = CK(t) P + SK(t) V
V(t) = −K SK(t) P + CK(t) V

Isometries use two ordinary scalar-first quaternions a + e b, with a commuting scalar e² = K. Their shared composition law is:

(a,b)(c,d) = (ac + Kbd, ad + bc)

This covers complex, dual and split quaternion pairs. The same linear action transports points and tangents. Scene construction, camera motion and rendering use these pairs throughout. The CPU geometry library checks isometry constraints; the GPU specializes the curvature sign while sharing advancement, frames and primitive solvers. Hyperbolic points lie on the hyperboloid. Half-space and ball charts provide useful ways to describe positions and surface patterns, with explicit conversions to and from embedded points.

Distance continues when coordinates repeat

On a sphere, s and s + 2πRn reach the same point and tangent, but they represent different optical paths. Every intersection therefore retains its actual forward physical distance. Queries use [minimum, maximum); periodic roots are lifted into that interval, and only the immediate numerical self-hit is suppressed. Later crossings of the same surface remain valid.

A complete circuit can establish a deterministic surface miss in a static scene. It cannot rule out a fog interaction on a later circuit. Medium sampling keeps the full travel distance before periodic phase reduction is used to evaluate coordinates.

2. A hyperbolic coordinate chart

The upper half-space chart makes geodesics, horospheres and their surface patterns easy to visualize. This section uses normalized curvature −1 (radius one). A chart point has coordinates p = (x, y, z) with z > 0. These coordinates describe positions; the metric determines physical distances:

ds2 = (dx2 + dy2 + dz2) / z2

A small coordinate displacement has hyperbolic length approximately its Euclidean length divided by z. Equal coordinate steps therefore cover more physical distance close to z = 0. The reference point is o = (0, 0, 1).

The plane z = 0, together with the point at infinity, is the ideal boundary, also called the absolute. It is not a wall that a ray can hit after a finite travel distance. Along a vertical line, the distance is |log(z₂ / z₁)|, which diverges as either endpoint approaches the boundary while the other stays fixed.

d(p, q) = 2 asinh( ‖p − q‖ / (2 √(pz qz)) )

This distance formula is equivalent to the usual inverse-hyperbolic-cosine expression. It is better suited to nearby points because it avoids subtracting nearly equal quantities around cosh(d) = 1.

3. What a straight ray means

Free light follows geodesics, the locally straight paths of the metric. In half-space coordinates they appear as vertical lines or circular arcs perpendicular to the boundary plane. Their coordinate curvature is not caused by a material bending the ray.

For example, two unit-speed paths starting at the reference point are:

Vertical:    γ(s) = (0, 0, eˢ)
Horizontal:  γ(s) = (tanh s, 0, 1 / cosh s)

The second begins in a horizontal direction but immediately curves in the coordinate picture. The tracing kernel evaluates embedded geodesics and orders hits by forward travel distance, without recovering that distance from endpoints. After a hit, the next ray uses the geodesic’s tangent at the hit point.

4. Isometries and camera motion

An isometry moves positions and orientations while preserving distances and angles. In every curvature, a normalized quaternion pair g = (a,b) satisfies:

‖a‖² + K ‖b‖² = 1,   a · b = 0

Encode an ambient vector P = (w,X) as the pair q(P) = ((w,0),(0,X)). Its transformed vector is the scalar part of the first quaternion and vector part of the second in:

g q(P) g†,   g† = (conjugate(a), −conjugate(b))

This action is linear in P, so it also transports tangents. The inverse isometry is (conjugate(a), conjugate(b)). Pair multiplication composes maps: outer.chain(inner) applies inner first. Camera and object transforms use these same operations.

Useful motions

For a unit spatial axis n, translation by physical distance L uses t = L/R in curved spaces and t = L in Euclidean space. Rotation through angle φ has the same formula in all three:

Translation: a = (CK(t/2), 0),  b = (0, n SK(t/2))
Rotation:    a = (cos(φ/2), n sin(φ/2)),  b = 0

The translation carries the origin along its geodesic with initial direction n. In the hyperbolic half-space picture, the +z translation scales all chart coordinates by eᵗ, while +x follows the horizontal-starting geodesic above. A constant horizontal chart shift is also an isometry, but follows a horocycle. Components that need that placement construct the corresponding pair explicitly.

The CPU retains canonical transforms in f64. Before rendering, it composes each object with the inverse camera, checks the resulting pair, and uploads f32 values. Camera movement updates one canonical transform and repeats this preparation, using the same representation for every geometry.

5. Transporting directions

A direction belongs to the tangent space at a point. Transforming only the position leaves the ray inconsistent. An embedded isometry transports both point and tangent through its linear action, preserving their manifold, orthogonality and unit-speed constraints.

Materials express directions as ordinary three-component vectors d in an orthonormal tangent frame. At the embedded point P = (w,X), the conversion to an ambient tangent is:

Euclidean:  V = (0, d)
Hyperbolic: V = (X · d, d + X (X · d)/(w + 1))
Spherical:  V = P × Quaternion(0, d)

The last expression uses quaternion multiplication. It defines a spherical frame even at antipodes. The hyperbolic expression is the canonical origin-to-point boost. These frames let reflection, refraction and diffuse scattering share their three-dimensional dot products while the ray retains an embedded tangent and an independent physical travel distance.

A coordinate conversion has its own differential. If a component derives chart coordinates c(P), the chart tangent is DcP[V]. Its Euclidean coordinate length generally differs from its metric length. Explicit conversion methods preserve that scale; material directions continue to use orthonormal frames.

6. Planes, horospheres, and tilings

The hyperbolic example contains two kinds of surfaces. Their spherical appearance in coordinates does not make them ordinary Euclidean spheres.

SurfaceHalf-space descriptionIntrinsic geometry
Geodesic planeA hemisphere centered on the boundary, or a vertical planeHyperbolic plane, curvature −1
HorosphereA sphere tangent to the boundary, or a horizontal planeEuclidean plane, curvature 0

The canonical embedded hyperbolic primitives are Z = 0 and w − Z = 1. In half-space coordinates these appear as the upper hemisphere x² + y² + z² = 1 and the horosphere z = 1. Object isometries place copies throughout the scene. To intersect a mapped object, transform the embedded ray into its local frame, solve the canonical intersection, then transport the hit and tangent back.

Geodesic planes and physical-radius spheres have analytic solvers in all three spaces; a spherical plane is a great 2-sphere, and a spherical sphere requires 0 < r < πR, subject to f32 representability checks. Isometries place shapes but do not resize curved spheres. Square and hexagonal patterns fit naturally on horospheres. The geodesic planes carry pentagonal and star patterns. Tiling components receive embedded positions and derive their pattern coordinates explicitly. The current pentagonal reduction uses a finite iteration depth, so the implementation does not promise an arbitrarily deep tessellation near the ideal boundary.

7. Materials and path tracing

Curvature changes ray propagation between interactions. At a surface, reflection and scattering are evaluated in its local tangent space. An orthonormal tangent frame lets the shader use ordinary three-dimensional dot products for angles in every geometry. Spherical frames use quaternion multiplication and remain defined at antipodes; hyperbolic frames use the canonical origin-to-point boost.

Each sample jitters a primary camera ray, finds the nearest hit, collects emission, chooses a material interaction, and continues with the new direction. A vacuum ray that misses samples the configured environment. In a medium, a surface miss first leaves an unbounded interval for a volume event; it does not immediately sample the environment. Repeated samples estimate the outgoing radiance; the GPU keeps a running sum and sample count.

Lo(p, ωo) = Le(p, ωo) + ∫hemisphere fr(p, ωi, ωo) Li(p, ωi) |n · ωi| dωi

This is the local reflection equation; transmissive materials also admit incoming directions on the other side of the surface. Hypertrace implements mixtures of diffuse, specular, transparent, and refractive interactions. The hyperbolic example uses straight-through transparency; the Euclidean sphere uses refraction.

The example scenes terminate paths after a fixed number of interactions: three in the hyperbolic scene, four in the Euclidean scene, and six in the spherical scene. Both surface and volume events consume this budget. The spherical example uses emissive objects and starts with a configurable black miss background. More samples reduce Monte Carlo noise, roughly as 1 / √N, but do not remove the bias from that finite bounce limit. The gallery previews record their own sample counts, source revision, camera and bounce settings in the linked render manifest; they are not evidence that every newer renderer change has been published.

Homogeneous fog

A homogeneous medium has scalar extinction σt per world unit and RGB scattering albedo. Free flight is sampled as s = −log(1 − u)/σt, then compared with the nearest surface distance. A surviving volume event scatters isotropically and multiplies throughput by albedo. The analog estimator has already sampled survival; multiplying by exp(−σts) again would count attenuation twice.

For diagnostics, a fixed segment has transmittance T(s) = exp(−σts). Two spherical segments can end with the same point and tangent but different T because one includes more complete circuits. The standalone eu-fog scene demonstrates Euclidean scattering around one bright light with red diffuse, green reflective and blue refractive spheres. Its scene source owns the medium settings; zero extinction selects vacuum and zero albedo gives pure absorption. Heterogeneous media and anisotropic scattering remain future work.

Samples are averaged in linear RGB. The preview then applies the renderer’s display transform, a gamma of 1/2.2, and clamps to the display range. Display conversion belongs after accumulation, not inside it.

8. Coordinate conversions

The Poincaré disk describes H². For this three-dimensional renderer, the corresponding bounded model is the Poincaré ball. It describes the same space, with different coordinates and the unit sphere as its ideal boundary.

One half-space-to-ball map taking (0, 0, 1) to the origin is:

A = x² + y² + (z + 1)²
C(x, y, z) = (2x, 2y, x² + y² + z² − 1) / A

ds² = 4 ‖db‖² / (1 − ‖b‖²)²

The hyperboloid provides the embedded representation used throughout Hypertrace. Its points satisfy w² − ‖X‖² = 1 with w > 0. For a half-space point h = (x,y,z), the conversion and its inverse are:

w = (‖h‖² + 1)/(2z),  X = (x/z, y/z, (‖h‖² − 1)/(2z))
h = (X₁, X₂, 1)/(w − X₃)

The Poincaré-ball coordinate is b = X/(w + 1). Conversely, w = (1 + ‖b‖²)/(1 − ‖b‖²) and X = 2b/(1 − ‖b‖²). These normalized coordinates are independent of R; physical lengths scale by R. The CPU geometry library exposes point conversions and their differentials explicitly. Applications can use them to construct embedded data, and surface components can derive the coordinates needed by their patterns.

Coordinate conversion leaves the represented point and geometry unchanged. The renderer stores embedded points, tangents and quaternion-pair maps throughout; choosing ball coordinates for a construction input does not select a different tracing kernel. Bounded ball coordinates approach their ideal boundary as distance grows, while hyperboloid coordinates grow exponentially. The Klein ball makes geodesics straight chords while losing conformality, so angle and material calculations need its metric.

9. Precision and current limits

No coordinate model gives uniform floating-point precision at the absolute. The boundary is infinitely far away: half-space heights approach zero, ball radii approach one, and hyperboloid coordinates grow without bound. Bounded coordinates alone do not solve cancellation or loss of relative precision.

The current implementation:

  • Composes canonical camera and object transforms in CPU f64, prepares objects relative to the camera, then uploads checked f32 pairs to the GPU.
  • Shares embedded advancement, tangent frames and analytic section solvers while preserving necessary zero-curvature and periodic-root cases.
  • Rejects transforms and sphere parameters that cannot be represented reliably by the f32 kernel; curved sphere radii must not collapse cosine or hyperbolic cosine to an endpoint or overflow the section equation.
  • Uses the same generated WGSL for native WGPU and browser WebGPU rendering.

Camera-relative coordinates are implemented before upload; they keep nearby values moderate without mutating canonical scene data. Recentring later path segments remains future work. Runtime guards detect nonfinite states and invalid manifold/tangent residuals; an emergency hyperbolic step bound prevents exponential overflow. A numerical failure terminates the path, retaining prior emission and adding no environment light. This introduces explicit truncation bias and is not a shorter-distance substitute for the requested path.

Accumulated travel is stored as a high multiple of 1024 world units and a separate remainder. Individual block increments remain exact below 2³⁴ total world units, but this bookkeeping range is not a coordinate-accuracy guarantee. Each segment remains f32; phase reduction cannot recover distance bits already lost in a very large segment. Hyperbolic cancellation can become significant far earlier. The geometry contract distinguishes the tested envelope, numerical guards, and distance representation.

The same generated code targets native WGPU and browser WebGPU. Native numerical tests and viewer smoke tests have been exercised, and the WASM build passes; a headed browser validation of the shared renderer remains outstanding.

Each example folder owns its scene.rs and main.rs, including renderer, presenter, and Wgame event-loop setup. The separate hypertrace-gallery package in examples/gallery imports those scenes through its hypertrace_gallery library for the gallery tools. The standalone example package has no library target or gallery dependency and uses the rendering libraries directly.
